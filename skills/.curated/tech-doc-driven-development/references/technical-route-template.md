# 技术路线文档模板

按完全体路线文档的紧凑格式生成。保留六个固定主章节，删除不适用的方案子节和占位说明；不要默认补管理元数据。

````markdown
# <YYYYMMDD> <需求名称>路线方案

# <核心方案名称>方案

## 背景

<用一段话说明当前问题、为什么现在要做，以及本需求相对现状的新增差异。>

## 目标

<用一段话写最终要达到的业务结果；尽可能给出量化标准，不写技术实现。>

## 整体链路

<默认只用一张 Mermaid 流程图展示从请求/输入到响应/输出的关键节点。流程图无法准确表达时，才补架构图或时序图。>

```mermaid
flowchart LR
  A[输入] --> B[准入或路由]
  B --> C[核心处理]
  C --> D[输出]
```

## 方案

<逐项对齐 PRD，把业务语言结合现有代码链路翻译成可落地的技术语言；保持准确、易懂，不下钻到文件、类或函数。>

### <必须先冻结的协议、数据或关键决策>

- <关键约束或输入>
- <关键处理规则>
- <降级或兼容规则>

### 涉及模块

| 模块 | 处理 |
| --- | --- |
| <模块或链路节点> | <该模块承担的处理、边界与关键约束> |

### <联调 / 发布 / 迁移方案，可选>

<写清执行顺序、门禁、状态核对和回滚方式。>

## 验收标准

- <代码落地后可观察、可逐项核对的实际表现>
- <失败、降级、兼容或回滚结果>

## 范围

- 本阶段包含：<范围>。
- 本阶段不包含：<范围>。
- <需要引用后续实现方案冻结细节时，在这里指向对应文档。>
````

检查：主章节固定为“背景、目标、整体链路、方案、验收标准、范围”。不了解项目的人应能在 10 分钟内复述这些内容。每个要点尽量不超过 100 个汉字，删掉不影响理解的文件级细节。
